## 1. What We Are Building

OralPath is a mobile-first diagnostic assistant that helps doctors analyze histopathological slide images for Oral Squamous Cell Carcinoma (OSCC). A doctor photographs a biopsy slide through a microscope, and the app returns a structured analysis: whether cancer is present, what grade it is, and what tissue components are visible in the slide.

This is not a replacement for a pathologist. It is a decision-support tool — designed for use in resource-limited settings, smaller clinics, and hospitals without dedicated oral pathology departments, where a doctor may need a rapid second opinion before referring a patient.

The app will be distributed free of charge. It will be developed as a research project and submitted for ICMR / DST grant funding. A defensive patent will be filed to prevent commercial entities from copying and selling the system.

---

## 2. The Problem

Oral Squamous Cell Carcinoma is among the most common cancers in India, with incidence rates significantly higher than global averages due to tobacco and betel nut use. Despite this, most districts lack access to qualified oral pathologists. The standard diagnostic pathway — biopsy, H&E staining, pathologist review — can take days to weeks, and in many settings, is simply unavailable.

Early and accurate grading of OSCC directly affects treatment decisions:

- **Well-differentiated (WD):** Better prognosis, conservative treatment often sufficient
- **Moderately-differentiated (MD):** Intermediate prognosis, combined therapy
- **Poorly-differentiated (PD):** Aggressive disease, urgent intervention required

Misclassification or delayed classification costs lives. An AI-assisted tool that can grade a slide in seconds — even as a preliminary read — changes this calculus significantly.

## 4. What the App Does

### Core Features (v1)

**Image Capture**
- Doctor attaches phone to microscope eyepiece (via clip-on adapter)
- App guides framing, exposure lock, and focus quality check
- Supports both direct photo capture and gallery upload of existing slide images

**Preprocessing Pipeline (on-device)**
- Automatic image quality assessment (blur detection, coverage check)
- Stain normalisation using the Macenko method to correct for inter-lab H&E variation
- Resize and normalization to model input specifications (224×224 or 300×300)
- All preprocessing runs locally — no raw image leaves the device unless explicitly exported

**AI Inference**
- Stage 1: Binary classification — OSCC vs Normal tissue
- Stage 2 (if OSCC detected): Grading — Well-differentiated / Moderately-differentiated / Poorly-differentiated
- Stage 3: Tissue component identification — epithelial region, stromal region, tumor-infiltrating lymphocytes (TILs), collagen fiber characteristics
- Confidence scores returned for every output
- Heatmap / attention overlay showing which regions drove the classification

**Result Display**
- Clean result card: classification, grade, confidence percentage
- Visual heatmap overlay on the captured image
- Plain-language summary written for a non-specialist (e.g., "High likelihood of moderately-differentiated OSCC. Recommend urgent referral.")
- Tissue component breakdown panel

**Patient Record**
- Local patient case storage (Room / SQLite — no cloud sync by default)
- Patient ID, date, slide site, magnification, diagnosis, confidence
- Image thumbnail stored alongside record
- Optional: export full case as a structured PDF report

**PDF Report Generation**
- Doctor name, institution, date
- Captured image + heatmap overlay
- AI classification + grade + confidence
- Tissue component findings
- Disclaimer: "This report is generated by an AI research tool and should be reviewed by a qualified pathologist before clinical decision-making."

### Future Features (v2+)

- Whole-slide image (WSI) support via tiled patch analysis
- Multi-image analysis per case (100× and 400× magnification views)
- Voice notes per case
- Anonymized case sharing for second opinion (doctor-to-doctor)
- Dashboard for tracking case history and referral outcomes
- Integration with ABDM (Ayushman Bharat Digital Mission) health records

## 5. How We Are Building It

### 5.1 Platform

**Primary:** Android (Kotlin)
- Minimum SDK: API 26 (Android 8.0) — covers ~95% of active Indian Android devices
- Target SDK: API 35
- Architecture: MVVM + Clean Architecture with UseCases
- DI: Hilt
- Navigation: Jetpack Navigation Component
- UI: Jetpack Compose

**Secondary (Phase 2):** iOS (Swift / SwiftUI)
- Shared model logic can be ported via ONNX Runtime (same model file, both platforms)

### 5.2 AI Model Architecture

#### Backbone Options (in priority order)

| Model | License | Use Case | Notes |
|---|---|---|---|
| EfficientNetB3 | Apache 2.0 | Primary commercial-safe backbone | Proven on OSCC Kaggle dataset, MIT-licensed fine-tunes available |
| DINOv2 (Meta ViT-L/14) | Apache 2.0 | Stronger feature extractor | Larger, may need quantization for mobile |
| CTransPath | MIT | Pathology-specific pre-training | 15M patches, 32 cancer subtypes |
| UNI (Harvard Mahmood Lab) | CC-BY-NC-ND 4.0 | Research validation only | Non-commercial; negotiate license before any deployment |
| CONCH (Harvard Mahmood Lab) | CC-BY-NC-ND 4.0 | Research validation only | Vision-language; allows text queries like "identify collagen" |

**Development strategy:**
- Train and validate with UNI/CONCH in research environment (permitted under NC license)
- Deploy with EfficientNetB3 or CTransPath backbone (Apache 2.0 / MIT)
- Negotiate UNI/CONCH commercial license from Mahmood Lab if their performance gap justifies it

#### Model Pipeline

```
Input Image (phone camera)
    │
    ▼
[Preprocessing — on device]
    ├── Quality check (blur score, coverage)
    ├── Stain normalisation (Macenko)
    └── Resize + normalize

    │
    ▼
[Feature Extraction — EfficientNetB3 backbone]
    │ (frozen or lightly fine-tuned)
    ▼
[Classification Head 1 — Binary]
    └── OSCC / Normal

    │ (if OSCC)
    ▼
[Classification Head 2 — Grading]
    └── WD / MD / PD

    │
    ▼
[Segmentation Head — Tissue Components]
    ├── Epithelial vs Stromal regions
    ├── TIL density estimation
    └── Collagen fiber characterization

    │
    ▼
[Attention / GradCAM Heatmap Generation]
    │
    ▼
Structured Result Output (JSON → UI)
```

#### Training Data

| Dataset | Images | Source | License |
|---|---|---|---|
| Kaggle OSCC (Tabassum et al.) | 1,224 (290 normal, 934 cancerous) | 230 patients, 100× and 400× | CC BY 4.0 |
| ORCHID Dataset | 23,000+ patches | Multi-center, WD/MD/PD graded | Open access |
| NDB-UFES | 3,763 patches (512×512) | OSCC / dysplasia / normal | Open access |

Training will be done in Google Colab (free tier) or Kaggle notebooks. Final model exported to:
- **ONNX** format for server-side inference
- **TFLite** (INT8 quantized) for on-device fallback

#### Inference Architecture

```
Primary path:
  App → Hugging Face Serverless Inference API
      → EfficientNetB3 (self-hosted model, free tier)
      → JSON response → App UI

Fallback path (offline / low connectivity):
  App → TFLite model (bundled, ~25MB)
      → On-device inference
      → JSON response → App UI
```

Hugging Face free tier: up to 30,000 requests/month. Sufficient for research-phase deployment across pilot hospitals.

## 6. Model Training Plan

### Step 1 — Environment Setup
- Google Colab Pro or Kaggle GPU (free)
- PyTorch + torchvision
- `timm` library for EfficientNetB3 / DINOv2 / CTransPath

### Step 2 — Dataset Preparation
- Download Kaggle OSCC dataset (1,224 images)
- Download ORCHID dataset patches
- Apply Macenko stain normalisation to entire dataset
- Split: 70% train / 15% validation / 15% test
- Augmentation: random flip, rotation, colour jitter, elastic distortion

### Step 3 — Stage 1 Training (Binary: OSCC vs Normal)
- Fine-tune EfficientNetB3 pretrained on ImageNet
- Loss: Binary cross-entropy
- Optimizer: AdamW, LR 1e-4 with cosine annealing
- Target: Sensitivity ≥ 0.95, Specificity ≥ 0.90 (matching published benchmarks)

### Step 4 — Stage 2 Training (Grading: WD / MD / PD)
- Multi-class head on same backbone
- Loss: Cross-entropy with label smoothing
- Use ORCHID graded dataset

### Step 5 — Stage 3 (Tissue Segmentation)
- DeepLabv3+ with Xception backbone (proven in OSCC literature)
- OR lightweight U-Net for mobile-friendly segmentation
- Trained on NDB-UFES patches with epithelial/stromal annotations

### Step 6 — Export
```python
# Export to TFLite (INT8 quantized)
converter = tf.lite.TFLiteConverter.from_saved_model(saved_model_dir)
converter.optimizations = [tf.lite.Optimize.DEFAULT]
tflite_model = converter.convert()

# Export to ONNX
torch.onnx.export(model, dummy_input, "oscc_model.onnx")
```

### Step 7 — Benchmarking
- Compare EfficientNetB3 vs DINOv2 vs CTransPath on held-out test set
- Compare against UNI/CONCH in research environment
- Report: AUC-ROC, sensitivity, specificity, F1, confusion matrix per class

## 7. IP and Legal Strategy

### Patent Strategy
- **Type:** Defensive patent — filed to prevent commercial copying, not to monetize
- **What to patent:** The system as a whole — mobile capture + stain normalisation + multi-stage classifier + structured clinical report output — as an apparatus/system claim, not a software claim
- **What NOT to claim:** The AI algorithm itself, the classification method in abstract — these will be rejected under Section 3(k) of the Indian Patents Act
- **Filing path:**
  - Provisional application first (~₹1,750 for startup/individual) — locks priority date
  - 12 months to file complete specification
  - Consider PCT filing simultaneously if international protection desired
- **Frame the claims as:** "A system for histopathological analysis comprising: [a mobile optical capture module], [a stain normalisation processor], [a multi-stage classification engine], [a structured clinical output generator]..."

### License Strategy
| Component | License Used | Notes |
|---|---|---|
| EfficientNetB3 weights | Apache 2.0 | Free for all use |
| CTransPath | MIT | Free for all use |
| UNI / CONCH | CC-BY-NC-ND 4.0 | Research/validation only |
| Kaggle OSCC dataset | CC BY 4.0 | Free for all use |
| ORCHID dataset | Open access | Verify terms before deployment |
| App code (OralPath) | MIT or Apache 2.0 | Open source |

### Distribution Strategy
- App distributed free on GitHub and/or Google Play (free listing)
- Positioned as a research tool with clinical disclaimer
- Registered under a university department or research trust (not a commercial company) to maintain NC compliance

### Regulatory Path (CDSCO)
- **Current phase:** Research tool with disclaimer — ethics committee approval from partner hospital(s)
- **Target classification:** Class C SaMD (moderate-high risk, cancer diagnostic)
- **Required before clinical adoption:**
  - CDSCO SaMD registration
  - Clinical validation study (prospective, multi-center)
  - Algorithm Change Protocol (ACP) for future model updates
  - Risk management documentation per ISO 14971
  - Quality Management System per ISO 13485

## 10. Risks and Mitigations

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| Model accuracy insufficient on real-world slides | Medium | High | Collect diverse staining conditions; include stain normalisation |
| UNI/CONCH commercial license denied | Low | Medium | Apache 2.0 backbone (EfficientNetB3) used as primary; UNI for validation only |
| CDSCO regulatory delay | High | Medium | Frame as research tool; partner hospital ethics approval bridges gap |
| Microscope camera image quality variance | High | High | On-device quality check + framing guide before capture |
| Patient data privacy breach | Low | Very High | All data local by default; no cloud sync; DPDPA 2023 compliant |
| Section 3(k) patent rejection | Medium | Low | Frame as system/apparatus claim; engage a patent attorney for drafting |
